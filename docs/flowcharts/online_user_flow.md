# 在线用户列表与在线变更通知流程

## 流程目标

向前端提供当前在线用户列表，并在在线状态变化时实时通知前端。

## 参与对象

- 浏览器前端
- HTTP 在线用户接口
- WebSocket 模块
- 在线用户模块
- 连接管理模块

## 前置条件

- 用户已经登录
- 若需要进入在线列表，则目标用户已建立 WebSocket 连接

## 在线列表查询主流程

1. 前端向 `/api/v1/users/online` 发起 HTTP 请求
2. 接口读取 `sessionId`
3. 鉴权模块校验 `sessionId`
4. 在线用户模块汇总当前在线用户昵称
5. 接口返回在线用户列表

## 在线变更通知流程

1. 某用户成功建立 WebSocket 连接
2. 在线用户模块把该用户标记为在线
3. 系统广播最新在线用户列表
4. 某用户断开 WebSocket 或登出
5. 在线用户模块把该用户标记为离线
6. 系统再次广播最新在线用户列表

## 异常流程

1. 如果 `sessionId` 无效，则拒绝在线列表查询
2. 如果当前没有在线用户，则返回空列表

## 关键规则

- 在线用户必须同时满足“已登录”和“WebSocket 已连接”
- 在线用户列表是私聊可选目标的重要来源
